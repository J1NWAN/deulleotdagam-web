# 01. 기획 사항 (확정)

> 상태 표기: ✅ 확정 · 🧪 프로토타입에서 정한 값(변경 가능) · ❓ 미정(→ `06-open-questions.md`)

## 서비스 이름
- ✅ **들렀다감** (프로젝트명 `deulleotdagam`, 표기 규칙은 `CLAUDE.md`의 "이름 규칙")
- ✅ 이름에 나무/트리 같은 오브젝트 이름을 넣지 않음 — 봄에는 벚꽃나무와 주변 사물, 여름에는 해변처럼 시즌마다 꾸미는 대상이 바뀌기 때문
- ✅ 서비스 이름은 고정, 시즌마다 부제만 교체 (예: "들렀다감 · 겨울 트리 꾸미기")

## 0. 아트 스타일
- ✅ **픽셀아트로 먼저 진행**. 플랫 등 다른 디자인은 추후 검토 (에셋과 프로토타입은 참고용으로 보관)

## 1. 서비스 형태
- ✅ 앱이 아닌 **웹 서비스**로 먼저 개발 (앱은 추후 검토)
- ✅ **회원가입 없는 게스트 기반**. "가볍게 즐기는" 컨셉 유지
- ✅ 무료 서비스, 무료 호스팅 사용
- ✅ 모바일 터치 대응 필수 (드래그 앤 드롭이 핵심 인터랙션)

## 2. 방(Room)
- ✅ 방을 만들면 **참여 코드**가 발급되고, 코드 또는 **공유 링크**로 입장
- ✅ **공개방 / 비공개방** 설정. 공개방은 "다른 사람의 공개된 방 접속하기" 버튼으로 랜덤 입장 가능
- ✅ **방장 재입장**: 방을 만들 때 방장 전용 **고유 ID(방장 키)** 를 레이어 팝업으로 최초 1회 안내하고, 이후 그 키로 접속하면 방장으로 인식
- ✅ 참여 코드/공유 링크와 방장 키는 **서로 다른 값**이어야 함 (참여자가 방장 권한을 얻는 상황 방지)
- ✅ **방장이 "방 삭제"를 직접 실행하면** 방을 **영구 삭제**
  - 브라우저를 닫거나 접속하지 않는 것은 삭제 사유가 아님 → 방장은 삭제하기 전까지 언제든 방장 키로 자기 방에 다시 들어올 수 있음
  - 삭제는 되돌릴 수 없으므로 확인 단계를 둘 것 (예: 방 이름을 입력하거나 확인 팝업을 한 번 더)
  - 삭제 시 접속 중인 참여자에게는 "방장이 방을 삭제했어요" 안내 후 연결 종료
  - 방장이 삭제하지 않은 방은 30일 자동 삭제 규칙(7절)으로만 정리됨
- ✅ 방 하나에 들어가는 오브젝트 수에는 상한이 있음 (슬롯 방식이므로 슬롯 수가 곧 상한)

## 3. 꾸미기 (핵심 인터랙션)
- ✅ 시즌 오브젝트(트리)에 기본 제공 장식을 **드래그 앤 드롭**으로 부착
- ✅ 부착할 때 **짧은 메모** 입력 가능 (선택 사항)
  - 🧪 메모 최대 40자
- ✅ 삭제 권한: 본인이 단 장식은 본인이 삭제 / 방장은 모든 장식 삭제 가능
- ✅ **슬롯(격자) 방식**으로 배치 제한 (자유 배치 아님)
- ✅ 시즌 오브젝트마다 슬롯 수가 다름, **최소 슬롯 수는 10개로 통일**
- 🧪 **한 방에 나무 3그루** (첫째/둘째/셋째 나무, 가운데 나무가 조금 더 큼)
- 🧪 나무마다 슬롯 위치와 개수를 **층별 구역 기반으로 랜덤 생성** — 상세는 `04-tree-and-slots.md`
  - 나무당 몸통 슬롯 10~14개 + 꼭대기 별 슬롯 1개
- 🧪 **꼭대기 슬롯은 별 전용**, 별은 꼭대기에만 달 수 있음
- 🧪 **조명/가랜드**(전구 줄, 금빛 가랜드, 구슬 줄, 요정 전구)는 사용자 장식이 아니라 **방장이 나무별·층별로 고르는 배경 장식** (2~4층에 하나씩, 없음 가능)
- 🧪 이미 누가 채운 슬롯에 동시에 장식을 달려고 하면 먼저 들어온 쪽이 이기고 나머지는 안내 메시지

## 4. 시즌 테마 확장
- ✅ 크리스마스 트리로 시작 → 봄 벚꽃나무, 여름 해변가, 가을 단풍나무, 겨울 크리스마스 트리
- ✅ 특별한 날(발렌타인, 할로윈 등) 테마도 추후 검토
- 설계상 "시즌 오브젝트"는 **윤곽 데이터 + 구역 정의 + 조명 위치 + 장식 목록**을 가진 설정 객체로 추상화할 것

## 5. 지난 시즌 방 둘러보기
- ✅ 모든 슬롯이 채워진(완성된) 방 중에서 **랜덤 노출**, **열람 전용**(장식 추가 불가, "읽기 전용" 배지)
- ✅ 완성된 방이 10개 미만이면 **미완성 방도 함께** 노출
- ✅ 조건을 만족하는 방이 없으면 **"지난 시즌에 완성된 (시즌에 맞게) 방이 없어요"** 문구
- ❓ 진행 중인 시즌 방도 포함하는지, 시즌이 끝나야 편입되는지

## 6. 실시간 동기화
- 원래 기획: 폴링으로 시작 → 사용자 증가 시 웹소켓
- ✅ **변경: 처음부터 웹소켓** (무료 호스팅의 요청 수 한도 때문에 폴링이 더 빨리 한도에 걸림. `02-tech-stack.md` 참고)

## 7. 자동 삭제 정책
- ✅ 방 생성 후 **30일 경과** + 설치된 장식 **5개 미만**이면 자동 삭제
- 목적: 저장소 관리, 의미 없는 방 최소화
- ❓ 나무가 3그루가 되면서 "5개"가 방 전체 기준인지 나무별 기준인지 확인 필요 (현재 해석: **방 전체 기준**)

## 8. 어뷰징 방지 / 모더레이션
- ✅ 방 생성 횟수를 **IP 또는 세션 기준으로 제한**
- ✅ **신고 기능 + 금칙어 필터** 도입
- ✅ 신고가 누적되면 **비활성방으로 전환** → 관리자가 유지/삭제 판단
- ✅ 개인정보(IP 등)는 **최소 수집**. 신고/차단/생성 제한 외 사용 금지, 개인정보처리방침 고지 필요
- ⚠️ 실제 적용 전 사용자가 법률 전문가 상담 예정 — 코드에서는 IP를 **원문 저장하지 말고 솔트 해시**로만 다룰 것

## 9. 완성 결과 공유
- ✅ 완성된 방을 이미지 등으로 공유
- ✅ 공유 시 **메모 포함 여부를 선택**하는 토글 (타인 메모 노출 방지)

## 10. 화면 목록
1. 메인/랜딩: 현재 시즌 소개, "방 만들기" / "코드로 입장하기" / "랜덤 공개방 입장하기", "지난 시즌 방 둘러보기" 진입점
2. 방 생성 직후 안내 팝업: 방장 키(강조, 분실 경고)와 참여 코드(공유용)를 **시각적으로 구분**해서 표시 — 프로토타입에 구현됨
3. 방 메인(꾸미기) 화면 — 프로토타입에 구현됨
4. 지난 시즌 방 둘러보기 (갤러리, 읽기 전용 배지, 빈 상태 화면)
5. 완성 결과 공유 화면 (메모 포함 토글)

1~3은 프로토타입이 있고, 4~5는 아직 화면 설계가 없습니다. 프로토타입과 같은 톤으로 만들어 주세요.
